# Parity: composer

Module: `:feature:composer`. iOS folders: `OpenCode/Composer/`. 48 files, 26,082 lines.

Composer host: `ComposerFeature.kt` / `ComposerView.kt` compose these ports into a working composer (draft, + menu with Photos/Files/Location, attachment chips and uploads, request dock answering permissions and forms, Today model picker, Send under `RetryPolicy.send`), configured by its parent with `ComposerFeature.Action.Configure(server, sessionID, directory)`. iOS keeps that state on `SessionFeature` (`SessionFeature+Send/+Requests/+Models/+Attachments`, `SessionView+Composer`), which the session area ports; until it wires these pieces itself, the host keeps the composer usable. The host polls pending requests every 2 s (iOS refreshes on SSE `permission.*`/`form.*`).

Types moved down into `:feature:composer` from `Session/` (session area uses them from here): `PendingPrompt` (`SessionFeature+Send.swift`), `DraftState`, `UndoSnapshot`, `DeliveryOutcome`, `SharedComposerDraft` (`ComposerPersistenceDrafts.kt`), `DictationHoldTracker`/`DictationDrag` (`MicPressGesture.kt`, from `DictationViews.swift`). Into `:server`: `PageShareRequest` (`Browser/BrowserFeature.swift`). `ComposerStagedFile`/`ComposerFileStaging` come from `:core` (`core/files`, the system area's move); `ComposerUriStaging` (`ComposerFileImport.kt`) stages picker `Uri`s into the same folder.
